# Figure it out — 临场编排剧本

当任务匹配不上任何更窄的剧本（如 `dev`）时，自己设计一个。动手写码前的交付物就是工作流本身：一串按任务规模伸缩严格度的阶段，跑科学方法假设循环，并留下人能在离开后审计的决策轨迹。

## Start

打开一个 todolist，第一项去读 `principles` 技能的 Principles 章节（设计/实现/验证/重构/并发/执行）。然后把下面的阶段加为待办。

## Phase A：Frame（框定）

先落地再承诺。开始跑之前必须能说清：

- 完成定义是一个**可证伪的谓词**（见 `principles` 的 prove-it-works）。
- 范围，量化：大致单元与工作量，以及框定阶段暴露的阻塞点。
- 严格度等级，偏向高。单向门（one-way door）与高破坏半径给更多；可逆低风险的步骤给更少。严格度是门禁与工件，不是「更努力」。

提交长程运行前先呈现框定与权衡。可逆工作直接推进（见 `principles` 的 never-block-on-the-human），但多小时的运行值得一个检查点。

## Phase B：设计工作流

拆成原子的、可独立落地的单元。风险最高/最未知者优先。脚手架与验证先于功能（见 `principles` 的 foundational-thinking）。

- 在工作之前就建好验证工装，基线从改动前状态捕获，使检查读作「旧值 vs 新值」。
- 对单向门设计决策，做一轮方案对比（2–3 个候选并排比较，择优）；机械性、形状已确定的活计跳过。在已定设计上再跑一轮 arena 是过度设计（见 `principles` 的 laziness-protocol）。
- 决定哪些扇出。只在接缝处并行，给每个工人自己的工作树或分支（见 `principles` 的 separate-before-serializing-shared-state）。勿过度扇出。
- 把设计出的阶段列表写下来——这份列表就是人审阅的对象。

然后执行设计。把它的步骤作为具体待办插入 Phase C 与 Phase D 之间，每步在 Phase C 的循环纪律下运行，并把 Phase D 的日志织入其中（每落一步写一行），而不是最后才存整条轨迹。

## Phase C：跑循环

每个单元是一次实验。陈述假设，做最小改动，对着真实产物上的谓词测量，推进了就留，没推进就回滚。应用 `principles` 的 sequence-verifiable-units：每单元验证完再开始下一单元，而非结尾批量检查。

- 通过检视产物来验证，绝不靠自报。某物过于轻易通过时，先怀疑观测方法再怀疑系统。
- 给委派工作配一个裁判。工人作弊绕过门禁就重置并硬化契约；门禁本身错了，就在它自己的改动里修门禁，而不是绕开它。
- 裁决只有三种：VERIFIED（已验证）、NOT VERIFIED（未验证）、INCONCLUSIVE（不确定）。不确定不是通过，别藏起否定。

## Phase D：保留审计轨迹

保留运行日志（可落到 `.dev/results.tsv`，或独立决策日志；长任务建议提交轨迹，使审阅者能在 PR 里读到）。轨迹加 diff，就是让人回来后能信任这份工作的东西。figure-it-out 的活计通常足够有野心，值得提交轨迹。

## Phase E：验证并交回

对着 Phase A 的谓词，在**真实产物**上（而非仅工装里）检查整体。把任何反复出现的纠正编码成门禁、lint 规则、检查或脚本（见 `principles` 的 encode-lessons-in-structure）。

**回复内容：** 你设计的工作流、严格度及其理由、决策轨迹路径、已对照谓词验证的部分、仍未闭环的部分。
